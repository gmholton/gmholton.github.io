The cognate matrix

Same letter in a row = same cognate set. Blank or ? = missing. Untick a row to drop it.

Paste your own data

Tab- or comma-separated. First row: meaning, Lang1, Lang2, …. Then one row per meaning with cognate-set labels (any letters or numbers). Up to 60 languages; '?', '-' or a blank cell means missing.

Distance: count, average, cluster

Lexicostatistics turns the matrix into one number per pair, then throws the characters away.

Percent shared cognates

Darker = more shared. Pairs are compared only on meanings where both have data.

UPGMA tree (lexicostatistics)

Proto is left out here: UPGMA always puts the root itself, between the two most different groups. The other trees on this page are rooted on Proto.

Joins the closest pair, averages, repeats. Assumes every language changes at the same rate, so it always produces a rooted tree with all tips lined up.

Neighbor-joining tree

Neighbor-joining uses the same distances but corrects for each language's overall distance from all the others, so a fast-changing language gets a long branch instead of being pushed to the edge of the tree.

The result is unrooted: it shows who groups with whom, not where the ancestor sits. Branch lengths are drawn to scale.

Neighbor-joining itself produces an unrooted tree. Here it is rooted on the proto-language, which is included as if it were a language with no changes. Branch lengths are drawn to scale.

NeighborNet network

NeighborNet uses the same distances but does not force them into a tree. Where the distances support two groupings that cannot both be in one tree, it draws both, and the conflict appears as a box of parallel edges.

A long, thin box means weak conflict; a fat box means strong conflict. Where there is no box, the data are tree-like. Like neighbor-joining, the network is unrooted, and edge lengths are drawn to scale.

MCMC: a random walk through tree space

Each step swaps two branches. Better trees are always accepted; worse ones only some of the time.

Press Step once to watch a single proposal, or Run to let the chain go.

How it decides: a tree that needs Δ more changes than the current one is accepted with probability e−βΔ. With β = 1, a tree 1 change worse is accepted about 37% of the time and one 2 changes worse about 14%. Higher β makes the walker stick close to the best trees; lower β lets it wander. A real Bayesian program uses a model of cognate gain and loss here instead of a change count.
